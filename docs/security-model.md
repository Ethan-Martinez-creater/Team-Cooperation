# 安全与信息隔离模型

## 1. 威胁假设

不可信输入包括用户文本、网页、邮件、文档、代码仓库、MCP 工具描述与结果、A2A 消息、模型输出和
从记忆中召回的内容。系统假设其中可能包含提示注入、秘密、伪造工具结果、恶意链接或持久化投毒。

## 2. 强制标签

每个资源具有：

- 所属租户；
- 分级：`PUBLIC < INTERNAL < CONFIDENTIAL < RESTRICTED`；
- compartment 集合（项目、客户、法务域等）；
- 来源、完整性和保留期元数据。

主体必须同时满足租户、clearance、compartment 和动作权限。跨租户流动默认拒绝，必须使用有范围、
有目的、有审批人、有失效时间的 `DisclosureGrant`。脱敏只能减少泄露风险，不能自动完成解密或降级。

## 3. 执行安全

- PDP 默认拒绝；LLM 不得签发角色、scope、审批或披露授权。
- 协作中的主导角色只拥有计划治理权，不自动获得安全管理员、数据所有者或高风险工具审批权。
- 高风险/关键工具即使角色允许也要求人工审批。
- 审批绑定主体、租户、具体动作、资源摘要、参数摘要和失效时间，不能被另一请求复用。
- Shell、浏览器、文档解析器和第三方 MCP 在隔离执行器中运行；凭据不进入模型上下文。
- 跨团队消息签名并校验时间窗和幂等键，防止篡改与重放。

## 4. Memory 安全

记忆分为会话工作记忆、团队项目记忆、组织知识和用户私有记忆。不同层独立命名空间、密钥和保留策略。
记忆条目保留 provenance、trust level、安全标签、写入主体和内容摘要。外部内容进入记忆前必须经过
注入检测、秘密检测、大小/频率限制和审批策略。召回内容以“不可信资料”注入，不能拼接到高信任系统
指令层。

## 5. 审计

关键决策记录 allow/deny/approval、策略版本、主体、资源摘要、工具参数摘要、模型/provider 元数据和
关联链，不记录明文密钥。当前 SQLite 实现使用每租户哈希链和 HMAC 完整性签名；生产环境的签名密钥
由 KMS/HSM 提供并轮换。

## 6. 上线门槛

- OIDC/OAuth2 身份接入与租户 claim 校验；
- PostgreSQL 行级安全策略和迁移测试；
- sandbox 逃逸、SSRF、提示注入、记忆投毒、跨租户越权的对抗测试；
- secret scanning、SBOM、依赖签名与镜像签名；
- 审批绕过、重放、幂等、灾难恢复和审计链验证；
- 数据驻留、备份、删除、保留与法律合规评审。
